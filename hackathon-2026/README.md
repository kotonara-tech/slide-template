# ことテク2026 2days ハッカソン チーム成果発表スライド テンプレート

2026年8月21日〜22日、BONCHI（奈良市橋本町3-1）で開催する **ことテク2026 2days ハッカソン** の
成果発表会で、各チームが使う発表スライドのテンプレートです。

見た目はリポジトリ直下と同じ **ことなら（kotonara.tech）ブランドテーマ**
（ブランドグリーン `#1A832A` ／ Bahnschrift・Segoe UI・游ゴシック ／ 5レイアウト）で統一されます。
チームは中身を書くことだけに集中してください。デザインは触らなくても整います。

対象読者は **参加チームと運営** です。

## 発表フォーマット

**発表 8分 ＋ デモ 2分 ＋ 質疑応答 3分程度**（登壇は入れ替え込みで約13分）。

スライドは9枚固定です。枚数と並びは変えず、中身だけを埋めてください。

| # | スライド | レイアウト | 時間 |
| --- | --- | --- | --- |
| 1 | `{{プロダクト名}}`（表紙・チーム紹介） | 表紙 | 0.5分 |
| 2 | 誰の、どんな課題か | タイトルとコンテンツ | 1.0分 |
| 3 | 解決アイデア（ひとことで） | タイトルとコンテンツ | 1.0分 |
| 4 | デモ：実際にお見せします | タイトルとコンテンツ | **デモ枠 2.0分** |
| 5 | MVPの範囲と使った技術 | 表 | 1.5分 |
| 6 | 技術的な工夫・チャレンジ | タイトルとコンテンツ | 1.5分 |
| 7 | チームでの開発 | 表 | 1.0分 |
| 8 | 運用と今後の展望 | タイトルとコンテンツ | 1.5分 |
| 9 | ご清聴ありがとうございました | クロージング | **質疑 3.0分** |

**発表 8.0分の内訳** = 0.5 ＋ 1.0 ＋ 1.0 ＋ 1.5 ＋ 1.5 ＋ 1.0 ＋ 1.5（スライド 1・2・3・5・6・7・8）。
これに **デモ 2.0分**（スライド4）と **質疑 3.0分**（スライド9）が別枠で乗ります。

時間配分は各スライドのスピーカーノートの先頭に `【1.5分】` のような形で埋め込んであります。
ノートは発表者向けの台本ガイドです。何をどう話すか・どの審査項目に効くか・実務的な注意まで
書いてあるので、練習のときはノート表示（PowerPoint の［表示］→［ノート］）で読んでください。

デモが本番で落ちるのが一番もったいないパターンです。**動いている画面の録画とスクリーンショットを
必ず手元に用意**してから登壇してください。

## 審査項目5つとスライドの対応

審査項目と右列の文言は Day2 の運営資料「審査項目：5つの観点」からの引用です。

| 審査項目 | 発表でのアピールポイント（目安） | 効くスライド |
| --- | --- | --- |
| テーマにのっとっているか | 「ことなら」の誰の、どんな課題かが具体的に語られている | 2・3 |
| 見た目 | 画面・デザイン・資料が伝わる形に整っている | 4（＋テーマで全枚数） |
| 面白さ | 着眼点や体験に「なるほど」「使ってみたい」がある | 3・4 |
| スキル感 | 2日間での実装の工夫・チャレンジが見える | 5・6 |
| チームワーク | 役割分担と全員の持ち味が発表からも見える | 1・7 |

5項目の多くは、コードの量ではなく **ストーリーと見せ方** で決まります。
「見た目」はこのテンプレートを使う時点でかなり担保されるので、残り時間はデモの磨き込みに使ってください。

## 使い方A（推奨）: Claude Code に埋めてもらう

このリポジトリを Claude Code で開き、チームの成果物リポジトリを渡すだけです。

```
/create-hackathon-slide <チームの成果物リポジトリのパスまたはURL>
```

コードと README を読んで `team-slide-template.md` のプレースホルダーを埋め、PPTX まで自動生成します。
出力先は `hackathon-2026/output/` です（`.gitignore` 済みなのでコミットされません）。

生成されたら**必ず中身を読んで直してください**。課題設定・運用の話・チームのエピソードは、
リポジトリを読んだだけでは書けません。そこが審査で一番見られる部分です。

## 使い方B（手動）: 自分で埋めてビルドする

1. `hackathon-2026/team-slide-template.md` を自分のファイルにコピーする

   ```powershell
   New-Item -ItemType Directory -Force hackathon-2026/output
   Copy-Item hackathon-2026/team-slide-template.md hackathon-2026/output/team1-slides.md
   ```

2. `{{...}}` を**すべて**埋める（全部で60か所）。`{{` `}}` ごと消して本文に置き換えます

3. python-pptx を入れる（初回だけ）

   ```powershell
   pip install python-pptx
   ```

4. リポジトリルートからビルドする

   ```powershell
   python hackathon-2026/scripts/build_hackathon_slide_pptx.py あなたの.md -o 出力.pptx
   ```

   `-o` を省くと `<mdと同じ場所>/<md名>-kotonara.pptx` に出力されます。

**`{{...}}` が1つでも残っていると、検証エラーになりビルドは失敗します**（終了コードが0以外になります）。
これは「埋め忘れたまま本番で投影する」事故を防ぐための仕様です。埋め忘れの場所はエラーに出ます。

### md を編集するときの約束ごと

ビルドスクリプトは Markdown を素朴に解釈します。次を守らないとビルドが落ちるか、
書いた内容が PPTX に出てきません。

- スライドの区切りは行頭 `---` の1行だけ。**それ以外の場所に `---` を書かない**（YAML フロントマターも禁止）
- 各スライドに `#` タイトルを1本。`##` サブタイトルは1枚目（表紙）だけ
- 箇条書きは `- `。ネストは半角スペース2個
- 表は GitHub 形式。**5枚目と7枚目だけ**が表スライドです。他の枚に表を足さない
- スピーカーノートは `<!-- note: ... -->` を各スライドに1個。ノート本文に `-->` を含めない
- 使えない記法: `**太字**`、`[リンク](URL)`、note 以外の HTML
- 見た目の目安: 箇条書きは1枚6項目まで・1項目40字前後まで。表はヘッダー行を含めて5行まで

## 見本 PPTX

`team-slide-template-kotonara.pptx` は、プレースホルダーがそのまま見えている状態の見本です。
「どこを書き換えるのか」「埋めたらどう見えるのか」を PowerPoint 上で確認できます。

再生成するときは `--template-mode` を付けて実行します（この場合だけプレースホルダー残存チェックが免除されます）。

```powershell
python hackathon-2026/scripts/build_hackathon_slide_pptx.py --template-mode
```

## テスト

ビルドスクリプトの受け入れテストです。スクリプトやテンプレートに手を入れたら必ず流してください。

```powershell
python -m pytest -q hackathon-2026/scripts/test_build_hackathon_slide_pptx.py
```

テストが担保しているのは、9枚構成・5枚目と7枚目が表・全スライドにスピーカーノートがある・
表紙のタイトルが `{{プロダクト名}}`・デモと質疑の時間がノートに刻まれている・
プレースホルダーが残った md はビルドが失敗する、といった点です。

## フォントについての注意

テーマのフォントは **Bahnschrift**（欧文見出し）／ **Segoe UI**（欧文本文）／ **游ゴシック**（和文）です。
いずれも Windows の標準フォントなので、Windows の PowerPoint では意図した通りに表示されます。

macOS・Linux・Google スライドで開くと**代替フォントに置き換わり、字送りや改行位置がずれます**。
発表本番は、できるだけ Windows ＋ PowerPoint で投影してください。
やむを得ず別の環境で開く場合は、事前に1枚ずつ見て、はみ出しや変な改行がないか確認してください。
PDF に書き出しておくのが一番安全なフォールバックです。
